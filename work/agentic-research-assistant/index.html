Agentic Research Assistant

Multi-agent research loop with memory that survives across sessions

An orchestrator, a research agent, and a reasoning agent working a Plan, Reason, Act loop over a dual-layer memory.

3 cooperating agents
35% fewer redundant retrieval calls
2 memory layers, episodic and semantic

Overview

Research assistants usually forget everything between sessions, so every conversation starts from zero. This one is built around memory: it keeps what it learned, deduplicates it, and picks up multi-session research threads where they left off.

How it works

  • Built on Google ADK with three agents: an orchestrator that plans, a research agent that gathers, and a reasoning agent that synthesizes.
  • A Plan, Reason, Act execution loop drives each research task from question to grounded answer.
  • Memory is dual-layer ChromaDB: episodic events from sessions, plus a long-term semantic store.
  • Hierarchical memory indexing deduplicates episodic events against the semantic store before retrieval.

Results

  • Reduced redundant retrieval calls by 35% through hierarchical memory indexing.
  • Maintained context across multi-session research workflows.
